# User Validation Checkpoints

## Purpose
These are the mandatory points where Codex should use judgment first and then loop Trevor in before treating a day as final.

## Required Validation Gates
### A. Metric Set
- Propose the lead metric.
- Propose the support metrics.
- Flag any metrics that overlap enough to create story confusion.
- Check that metric names can be rendered in intuitive labels, not just internal stat codes.
- Ask for confirmation before locking the day.

### B. Research Question and Core Idea
- Propose the exact research question.
- Propose the intended bracket-facing takeaway.
- Ask for confirmation before locking the day.

### C. Pattern Fit
- Decide whether the day should use the normal pattern:
  - context over time
  - pooled relationship
  - by-year or stability check
  - seed-band split
  - archetypes or interaction layer
  - era comparison
  - current-field application
- If yes, explain why.
- If no, propose the deviation and explain why.
- Ask for confirmation before locking the day.

### D. Visual Communication Readiness
- Confirm the chart titles will be obvious and legible.
- Confirm the metric labels can be understood by a bracket reader without decoding internal shorthand.
- Confirm the chart form matches the question being asked.
- Confirm the visual can be understood quickly without a long caption doing all the work.
- Ask for confirmation if a day needs a non-standard visual approach.

## Execution Rule
- Codex should make the first call.
- Trevor validates the decision after seeing the proposed structure.
- No day is considered locked until all required gates are cleared.

## Self-Review Rule
- Before handing back a day, Codex should review it at least twice.
- Review pass one: analytical structure, metric fit, and pattern fit.
- Review pass two: chart readability, label clarity, title visibility, and intuitive interpretation.
- If either pass finds a weakness, revise before presenting it as ready.
