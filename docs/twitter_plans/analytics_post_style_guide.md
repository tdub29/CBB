# Analytics Post Style Guide

## Purpose
This is a running record of your analytics-posting style.

It is descriptive first, not prescriptive. The point is to capture how you naturally frame analytics posts so future drafts stay aligned with your voice.

If your style changes, update this file. Do not use this file to overwrite the style already established in your posts.

## Reference Samples
Current style should be read from actual posts first, then from draft plans.

Primary local references right now:
- `docs/twitter_plans/sos/sos_day_1_thread_draft.md`
- `size tweet.pdf`

The PDF matters because it shows how the thread actually moved in public, not just how it was planned.

## Baseline Style
Based on the first SOS thread draft, your default style is:
- conversational
- seasonal and event-aware
- explanatory
- topic-led
- question-driven
- practical for bracket readers

Your posts do not read like formal research notes. They read like an informed analyst walking people through what matters.

## Opener Style
Your opener style currently does these things:
- sets the seasonal moment
- frames the series
- labels the day/topic clearly
- introduces the core question directly

That means your openers tend to feel like:
- `we're here`
- `here's today's topic`
- `here's the question`

This is a valid part of your voice and should be preserved unless you decide you want a sharper hook style later.

## Thread Framing Style
You naturally like to:
- orient the reader first
- explain what is being looked at
- move into evidence after setup
- build toward application later in the thread

So your thread voice is usually:
1. intro / setup
2. metric framing
3. evidence walkthrough
4. interpretation
5. present-year application

The `size tweet.pdf` sample confirms a more specific version of that flow:
1. series/day re-entry
2. metric definitions
3. broad historical setup
4. seed-controlled correction
5. seed-band nuance
6. support-signal nuance
7. present-year application
8. team-level speculation and matchup thoughts

That sequence should be treated as a strong default for future Day-style threads.

## Tone
Your tone is:
- casual but informed
- not overly polished
- not overly academic
- willing to speculate lightly, with caveats
- comfortable sounding like a real person rather than a cleaned-up brand voice

Important: do not sand off all of the conversational edges. That is part of the style.

The Size sample also shows that you are comfortable with:
- brief side comments
- light humor around data sourcing or odd player notes
- making a directional basketball read without pretending it is certainty

That should stay in bounds as long as the core analytical claim stays clear.

## Sentence Style
Your natural sentence patterns include:
- direct questions
- short setup lines before analysis
- conversational transitions like:
  - `Of course`
  - `That said`
  - `Now that we've looked at...`
  - `Now for the fun part...`

These transitions are part of the voice and should be treated as style markers, not noise.

The Size sample adds a few more recurring sentence habits:
- short declarative lead-ins before the chart point
- `Interestingly, ...`
- `In fact, ...`
- `Despite ...`
- `Though ...`
- `While ...`
- `This looks good for ...`
- `it's hard to say whether ...`

Those are useful because they let you move from evidence to interpretation without sounding formal.

## Analytics Style
You tend to present analytics in this way:
- start with the intuitive basketball question
- use the data to test it
- distinguish between broad correlation and actual predictive usefulness
- keep coming back to bracket relevance

You are not just presenting numbers. You are stress-testing common March ideas.

The Size thread makes the structure more explicit:
- define the metric set early
- show a broad descriptive trend
- immediately test whether that trend survives seed control
- narrow from overall effect to where it matters by seed range
- then layer in the secondary signal if it changes bracket use

That progression should be preserved. It is the clearest repeated analytical flow so far.

## Interpretation Style
Your interpretation style tends to:
- acknowledge the obvious first
- then complicate it
- then ask where the effect is actually useful

Examples of that structure:
- `Of course a tough strength of schedule correlates strongly with deep runs, but does it predict them?`
- `So when does SOS actually matter?`
- `Now that we've looked at the application of SOS, let's circle back to conferences.`

This pattern is important. It gives your posts a natural reasoning flow.

The Size sample reinforces that you often move through interpretation in this order:
1. broad trend
2. correction / limitation
3. where the effect does or does not matter
4. what that means for actual teams

That is a better description of your thread logic than a generic "hook then charts" template.

## Current-Year Application Style
You like to save the most reader-useful part for late in the thread:
- what does this say about this year
- which teams benefit
- which teams are risky
- which conferences matter

That means your threads should usually end with:
- a current-tournament application section
- named teams
- a few directional judgments

The Size sample sharpens this further:
- you move from broad field comments to specific teams
- then to matchup or path implications
- then to a final loose observation if a team/player detail is interesting enough

So the end of the thread should feel applied and basketball-specific, not like a sterile ranking dump.

## Visual Style Preferences Seen So Far
From the SOS work, your chart preferences are:
- readable on first glance
- minimal clutter
- labels big enough to matter
- direct annotations when useful
- no unnecessary gridlines
- visuals that support the narrative rather than replace it

You also prefer charts to answer a basketball question, not just display a model output.

The Size sample adds two practical rules:
- one chart per tweet is the normal unit
- tweet copy should do the argumentative work; the chart supports it

The chart should not need to carry the whole conclusion by itself.

## Tweet Flow Pattern From `size tweet.pdf`
This is the clearest observed execution pattern so far:

1. **Re-enter the series**
   - remind people what day it is
   - name the topic immediately
   - tell them there will be a current-year payoff later

2. **Define the metrics early**
   - explain what the metric names mean in plain language
   - do this before asking the reader to interpret any chart

3. **Show the broad historical shape**
   - one clean overall chart
   - one plain-language takeaway

4. **Correct the naive read**
   - use seed control or a sharper framing
   - explicitly tell the reader when the broad trend is less useful than it first looked

5. **Localize the effect**
   - move to seed bands or narrower contexts
   - answer where the signal actually matters

6. **Layer the support signal**
   - if there is a second concept, bring it in only after the main effect is clear
   - use it to refine the story, not replace it

7. **Apply it to the current field**
   - start broad
   - then name teams
   - then make directional bracket or matchup observations

This should be treated as the default tweet flow unless a future topic clearly needs a different order.

## What The Size Sample Confirms
From `size tweet.pdf`, the following are now locked in as part of your style:
- topic-first opener over pure shock-hook opener
- early metric-definition tweet
- fast move from descriptive pattern to predictive usefulness
- willingness to say when a signal is weak, narrow, or conditional
- stronger interest in `where does this matter?` than `does this correlate?`
- team callouts late in the thread, not early
- some conversational looseness and side observations are part of the voice

This should be used as reference when drafting future Day threads.

## What Should Be Preserved
Future drafts should preserve these characteristics from your current style:
- seasonal entry into the topic
- clear topic/day labeling
- a central basketball question early
- conversational transitions between sections
- a mix of descriptive and predictive framing
- explicit movement from analysis to bracket application

## What Should Not Happen
Do not use this guide to:
- make every post sound corporate
- strip out all conversational phrasing
- force every opener into the same hook template
- replace your setup-driven style with a completely different voice

If a future post needs a sharper hook, treat that as an intentional variation, not a rewrite of your overall style.

## Working Rule
When using this guide for future drafts:
- match the voice first
- improve clarity second
- tighten structure third

Do not reverse that order.
